# Box Agent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Windows tray app: hotkey → drag a box over anything → an OpenRouter vision model sees the box and autonomously clicks/types/scrolls inside it until done; self-updates from GitHub Releases.

**Architecture:** Pure-logic modules (`geometry`, `tools`, `llm`, `agent`, `updater`, `settings`) are fully unit-tested with fakes. Thin OS-facing modules (`capture`, `actions`) take injectable backends. Qt UI (`overlay`, `panel`, `app`) wires everything; the agent loop runs on a `QThread` and talks to the UI only via signals.

**Tech Stack:** Python 3.13, PySide6, mss, Pillow, pynput, httpx, keyring, pytest, PyInstaller, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-14-box-agent-design.md`

## Global Constraints

- Windows only. Python ≥ 3.13.
- Runtime deps exactly: `PySide6`, `mss`, `Pillow`, `pynput`, `httpx`, `keyring`. Dev: `pytest`, `pyinstaller`.
- Hotkeys: select `ctrl+shift+space`, stop `ctrl+shift+x`.
- Defaults: `max_steps` 25, `settle_delay` 0.6 s, screenshot long edge ≤ 1280 px, keep latest 3 screenshots in history.
- Out-of-box coordinates are **rejected, never clamped**.
- Blocked combos: `win`, `alt+tab`, `alt+f4`, `ctrl+alt+del`, `ctrl+w`, `ctrl+shift+esc` (any combo containing `win` is blocked).
- API key only in keyring (service `"BoxAgent"`, username `"openrouter"`), never in `settings.json`.
- Settings path: `%APPDATA%\BoxAgent\settings.json`.
- OpenRouter endpoint `https://openrouter.ai/api/v1/chat/completions`, header `X-Title: Box Agent`, timeout 60 s, `tool_choice: "required"`.
- Releases API: `https://api.github.com/repos/Solslfy/box-agent/releases/latest`; release asset name `BoxAgent.exe`; tags `vX.Y.Z`.
- Process must call `ctypes.windll.shcore.SetProcessDpiAwareness(2)` before any Qt/mss use.
- Run all commands from repo root with the venv: `.venv\Scripts\python -m pytest ...`.

## Review Focus

1. **Box on a monitor left of / above the primary** (negative virtual-desktop coords) → clicks land correctly. Test in Task 1.
2. **Model sends coordinates as floats or numeric strings** (`"120"`, `119.6`) → accepted and rounded; non-numeric → `ToolError`. Test in Task 3.
3. **Malformed JSON in tool-call arguments** → `ToolError` returned to the model, never a crash. Test in Task 3.
4. **Typing Unicode, emoji or multi-line text** → typed exactly; `\n` becomes Enter. Test in Task 5.
5. **Panic pressed during a `wait` or while an LLM request is in flight** → no further action executes; `wait` sleeps in ≤0.1 s slices checking the stop flag. Test in Task 6.

### Task 6: Agent loop

**Files:**
- Create: `box_agent/agent.py`
- Test: `tests/test_agent.py`

**Interfaces:**
- Consumes: `OpenRouterClient.chat`, `image_part`, `LLMError` (Task 4); `TOOLS`, `parse_tool_call`, `ToolError`, `Action` (Task 3); `Shot` (Task 5); `Executor.run/release_all` (Task 5).
- Produces:
  - `SYSTEM_PROMPT: str` (spec §4.3 text)
  - `@dataclass StepEvent(step: int, kind: Literal["action","error","info"], text: str)`
  - `@dataclass RunResult(status: Literal["done","stopped","limit","error"], answer: str)`
  - `prune_images(messages: list[dict], keep: int = 3) -> None` — in place; image parts beyond the latest `keep` become `{"type":"text","text":"[earlier screenshot removed]"}`
  - `class Agent(llm, capture: Callable[[], Shot], executor, stop: threading.Event, on_step: Callable[[StepEvent], None], max_steps: int = 25, settle_delay: float = 0.6, sleep: Callable[[float], None] = time.sleep)`
  - `.run(task: str) -> RunResult`

Message protocol (fixed — providers reject images inside `tool` messages):
- First user message: `[{"type":"text","text": f"Task: {task or DEFAULT_TASK}\nScreenshot is {w}x{h}px; (0,0) is top-left."}, image_part(png)]`. `DEFAULT_TASK = "Look at this and do whatever it obviously needs (solve it / answer it / complete it)."`
- After each assistant message: append it verbatim; then for an executed action append `{"role":"tool","tool_call_id":id,"content":description}` followed by a user message with the new screenshot text+image; for a `ToolError` with `call_id` append a `tool` message with `"Error: ..."` ; with `call_id is None` append a user message `"Error: ... Call exactly one tool."`.
- `wait`: sleep in 0.1 s slices, aborting if `stop` is set.
- Stop flag checked: at loop start, after `llm.chat` returns, and before `executor.run`. On stop → `executor.release_all()`, `RunResult("stopped", "Stopped by user")`.
- `FailsafeTriggered` from the executor → same as stop.
- `LLMError` → `RunResult("error", str(e))` (`AuthError` re-raised so the UI can open Settings).

  - `test_invalid_call_counts_as_step_and_continues` (out-of-box click then done → done; error event emitted)
  - `test_step_limit` (`max_steps=3`, always click → status `limit`, 3 LLM calls)
  - `test_stop_while_llm_in_flight` (FakeLLM sets `stop` inside `chat` and returns a click → executor never runs, status `stopped`, `release_all` called)
  - `test_stop_during_wait` (wait 5 s; fake sleep sets stop after first slice → status `stopped`, total slept < 0.5)
  - `test_llm_error_returns_error`
  - `test_prune_images_keeps_latest_3` (5 image messages → exactly 3 image parts remain, the last 3)
